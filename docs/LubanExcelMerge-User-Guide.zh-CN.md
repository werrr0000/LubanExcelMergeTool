# Luban Excel Merge 用户手册

## 适用范围

Luban Excel Merge 用于解决 Git 或 Fork 中 Luban `.xlsx` 工作簿的三方合并冲突。工具读取 BASE、LOCAL、REMOTE，并将确认后的结果原子保存到 MERGED。

正式发布版本：`1.2.2`。支持 Windows x64，公式重算优先使用 WPS 表格，无法使用时回退到 Microsoft Excel。

## 在 Fork 中使用

1. 在 Fork 中执行 merge 或 rebase。
2. 对冲突的 `.xlsx` 文件运行 Luban Excel Merge。
3. 等待 BASE、LOCAL、REMOTE 分析完成。
4. 逐项解决所有冲突和元数据复核项。
5. 检查 MERGED 表格后点击保存。
6. 如果检测到既有字段列被删除、修改或移动，在二次确认窗口中复核结构变化并确认保存。
7. 保存成功后，工具将当前 MERGED 标记为 resolved 并加入 staged。

仓库级配置、四文件参数和错误排查参见 [Fork / Git 集成指南](Fork-Git-Integration.zh-CN.md)。

## 表格颜色

- 红色：存在冲突，必须选择 BASE、LOCAL 或 REMOTE。
- 黄色：记录或内容被删除。
- 绿色：新增记录或内容。
- 浅蓝色：已经处理的修改，包括自动修改以及已经由用户选择结果的冲突。新增仍为绿色，删除仍为黄色。
- 橙色：Luban 元数据发生变化，需要重点复核。

## 冲突处理

- 点击单元格可处理单个冲突。
- 点击行号可选择该行包含的全部冲突。
- 点击列头可选择该列包含的全部冲突。
- 使用“接受 BASE”“接受 LOCAL”“接受 REMOTE”批量应用选择。
- 使用上一处、下一处跨工作表浏览冲突。
- 使用撤销和重做修正批量选择。

MERGED 区域会即时显示当前选择对应的最终结果。任何工作表仍有未解决冲突时，整本工作簿都不能保存。

## 自动合并结果浏览

点击窗口底部中央的“查看结果”按钮可逐格定位所有浅蓝色结果。集合包含工具自动处理的变化、已经存在于 LOCAL 且经三方规则自动接受的变化，以及用户已经选择 BASE、LOCAL 或 REMOTE 的冲突。撤销冲突选择后，对应格子会恢复为未处理颜色并立即从结果集合移除。

- 第一次点击定位第 1 处自动合并结果。
- 重复点击依次浏览后续自动合并结果。
- 可自动跨工作表切换。
- 到达最后一处后继续点击会回到第 1 处。
- BASE、LOCAL、REMOTE、MERGED 四张表始终同步定位。
- 左下角显示当前浅蓝色结果格总数；开始浏览后同时显示当前序号。

## 多工作表

顶部标签用于切换工作表，并显示每个工作表剩余的冲突数量。BASE、LOCAL、REMOTE 的工作表名称、数量和顺序必须一致。

每个工作表独立分析，但保存以整个工作簿为单位。所有工作表的冲突和元数据复核项都完成后才能保存。

## Luban 元数据复核

不改变既有字段布局的元数据内容变化会以橙色高亮进入复核流程。用户必须明确选择 BASE、LOCAL 或 REMOTE。

工具支持 LOCAL 或 REMOTE 在任意位置新增字段列：

- 单侧新增字段会自动写入 MERGED，并可通过底部中央的“查看结果”按钮逐处查看。
- MERGED 以 LOCAL 的字段布局为基准；LOCAL、REMOTE 分别新增不同字段时保留双方字段，列位碰撞的远端字段移动到首个安全空列。
- 两侧新增同名字段但数据不同会进入内容冲突；类型或元数据不同会进入橙色元数据复核。
- 新字段数据按主键对齐，远端新增记录会携带完整新字段值。

`__tables__.csv` 中声明为 `mode=one` 的单例逻辑表也支持合并。BASE、LOCAL、REMOTE 必须各有且只有一条数据记录，工具不要求主键，而是对这条记录的每个字段执行三方规则：单边修改和双方相同修改自动合并，双方不同修改进入字段冲突复核。缺少记录或存在多条记录时会阻止保存，以保证生成结果仍符合 Luban 的单例表约束。
- 仅包含样式或格式的空行、空列不会参与数据边界计算；新增记录和字段会紧接最后一个有内容的行、列写入。
- 保存 MERGED 时会自动移除纯格式空行、纯格式空列及其空白单元格，并将工作表使用区域收缩到实际内容范围。有内容行列上的格式和公式会保留，清理过程不会移动任何有效单元格坐标。

既有字段列的删除、重命名、类型修改和位置移动使用与行记录一致的三方规则：

- 仅一侧变化、另一侧保持 BASE 时自动采用变化侧。
- LOCAL 和 REMOTE 做出相同变化时自动合并一次。
- 一侧删除、另一侧修改时产生删除/修改冲突。
- 两侧对同一字段做出不同修改或移动时产生列结构冲突，必须选择 BASE、LOCAL 或 REMOTE。
- 不同字段上的兼容变化会合并到同一目标布局；列位碰撞时优先保留 LOCAL 列位，其他字段移动到安全空列。
- 列结构选择和行数据选择在保存时统一映射到最终列号，避免数据写回旧列。

只要三方中存在既有字段列删除、修改或移动，点击“保存 MERGED”后都会显示二次确认窗口。窗口默认选择“否”并列出结构变化；取消后不会写入 MERGED、运行项目校验或执行 Git staging，确认后继续正常的原子保存和后续流程。

支持插入或删除 Luban 元数据行。元数据行数量或数据起始行变化会以橙色高亮进入复核，用户选择 BASE、LOCAL 或 REMOTE 后，工具会自动移动后续数据行。删除唯一可用的主键字段后，如果无法建立可靠的行身份，主键校验会阻止合并。

## WPS 与公式

默认模式为 `auto`：

- 不影响公式时不会启动办公软件。
- 公式可能受影响时优先调用 WPS 表格完成重算。
- WPS 不可用时尝试 Microsoft Excel。
- `auto` 模式下，Office 自动化不可用、失败或超过 30 秒时，会安全保存已经通过结构验证的 MERGED，保留来源公式缓存，并标记下次打开时完整重算。
- `always` 模式保持严格语义，重算失败时不会覆盖已有 MERGED。

选择 `never` 时，工具保留来源缓存并标记下次打开完整重算。保存后应使用 WPS 打开并保存一次以确认公式结果。

列移动会保留三方工作簿中已有的公式文本并触发重算，但工具不会猜测或重写公式引用。若字段移动会改变引用地址，应确保所选分支中的公式已经反映目标列布局，并在二次确认窗口和保存后的 WPS/Excel 结果中重点复核。

## 诊断与性能

日志默认位于 `%LOCALAPPDATA%\LubanExcelMerge\logs\日期`。日志包含三个输入文件读取时间、工作表分析时间和总耗时，但不记录单元格正文。

工具栏中的诊断按钮可导出不包含工作簿的诊断包。大表出现异常等待时，应保留诊断包以及工作簿行数、列数和工作表数量。

## 保存安全

- MERGED 使用临时文件和原子替换写入。
- 保存期间显示“保存中...”进度窗口，主窗口及红色关闭按钮会暂时禁用，保存成功或失败后自动恢复。
- 写入后会重新打开并验证工作簿。
- 项目校验失败时恢复保存前文件。
- Git 暂存失败时保留已经生成的 MERGED，并显示具体 Git 错误。
- 工具只暂存当前 MERGED，不执行 `git add .`。

## 当前限制

- 合并输入必须为 `.xlsx`。
- 每个参与合并的工作表必须能够解析为平面 Luban 表。
- 三方工作簿的工作表名称、数量和顺序必须一致。
- 多工作表模式暂不与全逻辑表唯一性扫描同时启用。
- 说明页、图表页或层级结构表不参与自动合并。
- 元数据行增删必须经过橙色元数据复核，确认后才允许保存。
